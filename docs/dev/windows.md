# Window sizes

Linked from the app page. The test is WindowMetricsTest.

Menu 488 by 95 + rows * 41, at most 760. One to three actions are one row. The 95 baseline is the previous 87 plus 8 px for the compact 34 px field. The earlier 56 px field had used 117. The row step remains 41. The one-row menu was not remeasured live after the compact-field adjustment. Banner 326×120. Its heading names the application when that application has a prompt note. Result 818×612 with chips, 818×576 with a refine field and no chips, or 818×563 for a report. Settings 886×780. Editor 798×545. History 998×456. Action card 663×720. Application card 748×440. Quick card 658×380. A saved card smaller than that design is opened at the design size. Key conflict 455×222. On Windows a decorated window adds the measured gap between `GetWindowRect` and the DWM frame, after the window is shown. Compose 1.12.2 uses the dp number as pixels. The menu opens beside the input field when the selection is in one, and beside the cursor when the selection is on a page. The side nearest the cursor is used when it stays on screen and does not cover that anchor. The point is kept inside the nearest work area, with a 6 px margin. The menu and the busy banner do not add the gap. Settings, the editor, history, result windows and editor cards write their outer frame to `windows.properties` when they move or resize, and open there next time. A saved frame that misses every monitor is shifted onto the nearest one. The menu and the banner are not saved: they follow the caret or the corner. A decorated window cannot be resized below the size it opened at. The banner sits at the bottom-right of the work area that contains the menu point, which follows the input window. A repeat with no menu uses that window, and the cursor only when the window is unknown. The banner shows the estimated token count and cost, then the provider's counts. A point on that monitor's taskbar still selects it. A point outside every work area uses the first area.
