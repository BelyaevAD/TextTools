# Error reports

Linked from the app page. The test is SentrySetupTest.

Both switches start off. `config/sentry.properties` is read beside the working directory, then beside its parent, then from `%LOCALAPPDATA%\TextTools\sentry.properties`. `:app:run` uses the app module as the working directory, so the repo file is the parent one. With the error switch on, a crash and a failed model call, settings call, settings save, or history write are sent. A chat completion that receives no response bytes for 180 seconds is one of those failed model calls. Bearer tokens and proxy passwords are removed from the text. The trace switch enables only hourly aggregates from `usage_event`, not an event per request. Counts, model ids, outcomes, character lengths, monotonic durations and reported tokens are grouped by completed hour and model. No prompt, response, window title, executable name, URL or credential is sent. Local recording continues while the switch is off. A disabled switch or blank DSN sends nothing. `traces-sample-rate` applies to future transactions, not metrics. Sentry's flush is not a delivery acknowledgement, so retry remains conservative. An orderly exit attempts the same completed-hour send before the database closes. GlitchTip metrics support must be checked on a test project before relying on external delivery; local statistics work regardless.
