# App profiling

Linked from the app page. The test is AppProfilingTest.

The hotkey snapshots the source process, window title and window class before focus moves. An unknown process is stored at once with an empty title and an empty hint, and the lookup starts in the background when profiling is on. A failed lookup can run again. UNKNOWN is stored and is not asked again. An OpenRouter `:online` refusal is retried without that suffix. The editor shows the factory profiles when the table is empty. A blank profiling model uses the default model. On OpenRouter the model id gains `:online` unless it already ends that way. Any other host keeps the id. Web notes are sent only when the search returned text, and the prompt tells the model to use a hit only when it names this executable.

The answer is two lines, `DESC:` and `HINT:`, or exactly `UNKNOWN`. An empty body, a leading `UNKNOWN`, or a body with neither line leaves the profile neutral. A parsed note is written onto the last neutral row of that process. Other rows stay. Title matching is `matchApp` on the domain page.
