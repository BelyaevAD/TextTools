## Conclusion

Четыре текста, по которым спрашивалась готовность, держат разные двери, и зелёная дверь не открывает остальные. Навык отпускает тег после чистых установщиков, честных заметок и одного коммита. CI на каждый push проверяет тесты и dokka и установщик при этом не собирает. Канон останавливает ход, пока портальный клон не увидит id и title, и локальный `index: ready` эту остановку уже выполнил только на диске. Поставка секретом тег не держит. Отсюда ширина коммита, которую ни один из текстов не выписывает целиком: он шире пары changelog и README, потому что иначе пакет останется 1.1.0, а портал останется на `pending`, и он уже, чем весь `git status`, потому что копии сайта v1.1 в `main` навык не кладёт.

Практическое следствие для следующего среза лежит в порядке, а не в ещё одном прогоне тестов. Команда, с которой навык начинает релиз, сносит `build`, и сегодняшние XML 128 тестов этот `clean` не переживут; свидетельством они остаются в заметках аудита, а воротами установщика не становятся. Пока в `dist/` нет файла, имя которого черновик уже напечатал, любой тег на текущем тексте changelog опубликует ссылку на отсутствующий ассет. Неизвестный результат GitHub Actions и неизвестный список файлов на GitHub Release нельзя зачислить ни в сдачу, ни в провал: их просто не спрашивали.
